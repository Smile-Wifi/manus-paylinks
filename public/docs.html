Developer API

Connect any page.

Create a payment request from your server and redirect the customer to the returned checkout URL.

Create payment

POST /api/v1/payment-requests

curl -X POST https://YOUR-GATEWAY/api/v1/payment-requests \
  -H 'Authorization: Bearer YOUR_GATEWAY_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"amount":"25.00","currency":"SGD","name":"Jane Customer","email":"jane@example.com","purpose":"Order 1001","reference_number":"ORDER-1001","redirect_url":"https://your-site.com/paid","webhook_url":"https://your-site.com/api/payment-webhook"}'

Redirect the browser to payment.checkout_url.

Success notifications

When the payment succeeds, the gateway sends a server-to-server payment.succeeded POST to your webhook_url. It includes X-Gateway-Signature, an HMAC-SHA256 signature of the raw JSON body.

{"type":"payment.succeeded","data":{"payment":{"reference":"ORDER-1001","status":"completed","amount":"25.00"}}}

Verify the signature with your shared webhook secret before fulfilling the order.

Check status

GET /api/v1/payment-requests/:reference

Use the same Bearer key. Treat a payment as paid only after a confirmed webhook or status response.

CMS admin

Open /admin and enter the protected ADMIN_API_KEY to customize branding, copy, colors, supported currencies, default payment URLs, and the default success webhook. Settings are persisted in the managed database.

Important

Keep the gateway API key and admin key in protected server configuration. Never expose them in browser JavaScript. In mock mode, checkout is simulated. In live mode, the gateway forwards requests to HitPay.
